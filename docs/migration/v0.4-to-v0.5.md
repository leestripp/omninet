# Migration Guide: v0.4.0 → v0.5.0

OmniNet v0.5.0 introduces async I/O, modern error handling, and non-blocking
logging. All changes are **backward-compatible** — existing code continues
to work. This guide helps you adopt the new features incrementally.

## What's New in v0.5.0

| Module | Description |
|--------|-------------|
| `OmniNet::Thread::ThreadPool` | C++23 work-stealing thread pool |
| `OmniNet::Async::Task<T>` | C++20 coroutine return type |
| `OmniNet::IO::IoContext` | Linux epoll event loop |
| `OmniNet::IO::AsyncSocket` | Non-blocking socket wrapper |
| `OmniNet::IO::AsyncFile` | Async file I/O via thread pool |
| `OmniNet::Async::AsyncLogger` | Non-blocking logger |
| `OmniNet::Async::AsyncTlsSocket` | Coroutine-friendly TLS |
| `OmniNet::Server::AsyncServer` | Event-loop HTTP server |
| `OmniNet::DB::AsyncDatabase` | Async DB wrapper |
| `OmniNet::DB::DatabasePool` | Connection pooling |
| `OmniNet::Result<T, E>` | `std::expected<T, E>` alias |
| `OmniNet::SocketError` / `DbError` | Error enums |

## New APIs (Opt-in Adoption)

You can adopt new features one at a time. Existing code continues to work
alongside new code.

### 1. Modern Error Handling with `std::expected`

**Before** (v0.4.0):
```cpp
try {
    db.open("/data/app.db");
    db.execute("CREATE TABLE ...");
} catch (const DatabaseException& e) {
    std::cerr << "DB error: " << e.what() << "\n";
    return;
}
```

**After** (v0.5.0):
```cpp
auto result = db.tryOpen("/data/app.db");
if (!result) {
    std::cerr << "DB error: " << toString(result.error()) << "\n";
    return;
}
db.execute("CREATE TABLE ...");  // Can still use void API
```

**When to migrate**:
- Hot paths where errors are common
- APIs that return optional data
- When you want compile-time error checking

**Performance**: `std::expected` is **49x faster on error paths**,
slightly slower (~5x) on success paths. See `expected_overhead_bench`.

### 2. Async Coroutines

**Before** (v0.4.0):
```cpp
// Synchronous handler - blocks the worker thread
server.get("/api/users", [](const Request& req, Response& resp) {
    auto db = pool.acquire();  // blocks
    auto rows = db.query("SELECT ...");  // blocks
    resp.setBody(format(rows));
});
```

**After** (v0.5.0):
```cpp
// Async handler - never blocks the event loop
server.get("/api/users", Async::AsyncHandler{
    [](const Request& req, Async::Executor& exec) -> Async::Task<Response> {
        auto pool = ...;
        auto dbOpt = co_await pool->acquire_async();
        if (!dbOpt) co_return Response::internalError("DB unavailable");
        auto rows = co_await (*dbOpt)->query("SELECT ...");
        Response resp;
        resp.setBody(format(rows));
        co_return resp;
    }
});
```

**When to migrate**:
- New endpoints that need database access
- I/O-bound operations (file, network)
- Endpoints with multiple sequential async operations

**Trade-off**: Coroutines have ~50x overhead vs regular functions due to
heap-allocated frames. See `coroutine_overhead_bench`.

### 3. Non-blocking Logging

**Before** (v0.4.0):
```cpp
// Each log call may block on disk I/O
Logger::instance().info("Processing request " + id);
```

**After** (v0.5.0):
```cpp
AsyncLogger logger(pool);
logger.info("Processing request " + id);  // Non-blocking!
logger.flush();  // Only when needed
```

**Throughput**: AsyncLogger achieves **32k+ msg/s** even with full
formatting and stdout output. Without console output: 1M+ msg/s expected.

### 4. AsyncServer (Event-Loop HTTP)

**Before** (v0.4.0):
```cpp
// One thread per connection
Server server(config);
server.get("/api", syncHandler);
server.start();
```

**After** (v0.5.0):
```cpp
// Event loop + thread pool
AsyncServer server(ioContext, config);
server.get("/api", Async::AsyncHandler{...});
server.run();
```

**When to migrate**:
- High-concurrency servers (10k+ connections)
- Async-first APIs
- New applications (no backward compat needed)

**Note**: Existing `Server` still works for legacy applications. You can
mix and match in the same process.

## Step-by-Step Migration

### Step 1: Enable `std::expected` for New Code

Keep existing void/throw APIs. Use `try*()` for new code:

```cpp
// Existing code unchanged
void oldFunction(Database& db) {
    db.open("/data/app.db");  // throws on failure
}

// New code uses try*()
void newFunction(Database& db) {
    auto r = db.tryOpen("/data/app.db");
    if (!r) {
        logError(toString(r.error()));
        return;
    }
    // ... use db normally ...
}
```

### Step 2: Add AsyncLogger to Hot Paths

```cpp
// In your application setup
Thread::ThreadPool pool({.workerCount = 4});
Async::AsyncLogger logger(pool);
logger.setLogFile("/var/log/app.log");

// Use it in any thread
logger.info("Request processed");
```

### Step 3: Migrate Critical Endpoints to Async

Pick 1-2 of your most important endpoints and migrate them to async:

```cpp
// Before (sync)
server.get("/api/heavy", [](const auto& req, auto& resp) {
    auto data = doExpensiveWork();  // blocks
    resp.setBody(data);
});

// After (async)
server.get("/api/heavy", Async::AsyncHandler{
    [](const auto& req, auto& exec) -> Async::Task<Response> {
        Response resp;
        // Do work in thread pool - doesn't block event loop
        auto data = co_await exec.submit(doExpensiveWork);
        resp.setBody(std::move(data));
        co_return resp;
    }
});
```

### Step 4: Use DatabasePool for Concurrency

```cpp
// Before (single connection)
Database db(*exec, "/data/app.db");

// After (connection pool)
DatabasePool pool(*exec, "/data/app.db");

// In handlers
server.get("/api/data", Async::AsyncHandler{
    [](const auto& req, auto& exec) -> Async::Task<Response> {
        auto dbOpt = co_await pool.acquire_async();
        if (!dbOpt) co_return Response::internalError("DB unavailable");
        auto rows = co_await (*dbOpt)->query("SELECT ...");
        pool.release(*dbOpt);
        // ...
    }
});
```

## Common Pitfalls

1. **Coroutine lifetime**: A `Task<T>` must be awaited or destroyed properly.
   Never leak coroutine frames.

2. **DatabasePool release**: Always call `pool.release(db)` after use, or
   connections will leak. RAII wrappers recommended.

3. **AsyncLogger shutdown**: Call `logger.shutdown()` before exit, or use
   RAII. The destructor does flush, but explicit shutdown is clearer.

4. **std::expected unwrapping**: Don't use `.value()` or `.error()` without
   checking `.has_value()` first. The whole point is type-safe error handling.

5. **Mixing sync and async**: You can have both `Server` and `AsyncServer`
   in the same process. But handlers should be either sync OR async, not
   a mix of both.
