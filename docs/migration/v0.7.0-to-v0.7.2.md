# Migration Guide: v0.7.0 → v0.7.2

OmniNet v0.7.1 and v0.7.2 are **bug-fix releases**. All changes are
backward-compatible — existing code continues to work. This guide
covers the 11 bugs fixed across the two releases and any
recommended adoption patterns.

## Breaking Changes

**None.** Both releases are backward-compatible. The bug fixes either:
- Fix deadlocks that were hanging code (now just works)
- Fix silent data corruption (now returns correct data)
- Add previously-unimplemented APIs (new code path; old path still works)
- Remove dead code (no callers, no impact)

## Recommended Actions

### 1. **Remove workarounds for `IntrusionDetector::checkAndBlock()` hangs**

If your code was working around BUG-1 (e.g., disabling the intrusion
detector, using your own regex middleware instead), you can now
remove the workaround. The deadlock is fixed.

**Before** (0.7.0):
```cpp
// Workaround: bypass IntrusionDetector entirely
m_http->use([](const Request& req, Response& resp) {
    // inline regex middleware here
    return true;
});
```

**After** (0.7.2):
```cpp
// Just use IntrusionDetector — it no longer deadlocks
m_ids->checkAndBlock(clientIp, method, path, &req);
```

### 2. **Verify CORS configuration works as intended**

If you were relying on the old (broken) CSV behavior, your config
may have been silently broken. Re-test:

**Before** (0.7.0, broken):
```cpp
sc.corsAllowedOrigins = "https://a.com,https://b.com";
// Server emitted: Access-Control-Allow-Origin: https://a.com,https://b.com
// Browsers REJECTED this (invalid per CORS spec)
```

**After** (0.7.2, correct):
```cpp
sc.corsAllowedOrigins = "https://a.com,https://b.com";
// Server parses to allowlist: {"https://a.com", "https://b.com"}
// For each request:
//   - If Origin header matches one in allowlist:
//       echo it back + Vary: Origin + Access-Control-Allow-Credentials: true
//   - If Origin header is "*" (special case):
//       emit "*"
//   - Otherwise:
//       omit Access-Control-Allow-Origin (browser blocks response)
```

If you want to revert to the old "allow all" behavior, set:
```cpp
sc.corsAllowedOrigins = "*";
```

### 3. **Switch to `TLSContext` factory pattern (recommended)**

If you were constructing `TLSSocket` directly with no context
management, consider switching to the new factory pattern:

**Before** (0.7.0, still works):
```cpp
TLSSocket sock;
sock.connect("api.github.com", 443);
```

**After** (0.7.2, recommended):
```cpp
auto ctx = OmniNet::TLSContext::createClient();
auto sock = ctx->createSocket();
sock->connect("api.github.com", 443);
// SSL_CTX is shared — multiple sockets can use the same context
```

Benefits of the factory pattern:
- **System CA bundle loaded by default** (no more silent cert acceptance)
- **SSL_VERIFY_PEER set by default** (secure out of the box)
- **Shared context** — create one SSL_CTX, use it for many sockets (saves memory + load time)
- **Cleaner API** — no more "forgot to call setVerifyMode()" footguns

### 4. **Add ALPN protocols to HTTPS client code**

If you're calling `https://` URLs and getting garbage status lines
like `PRI * HTTP/2.0`, you need ALPN:

**Before** (0.7.0, no-op):
```cpp
TLSSocket sock;
sock.setALPNProtocols({"h2", "http/1.1"});  // did nothing
sock.connect("api.github.com", 443);       // server picks default (h2)
// Client tries to parse h2 binary frames as HTTP/1.1 → garbage
```

**After** (0.7.2, works):
```cpp
TLSSocket sock;
sock.setALPNProtocols({"h2", "http/1.1"});  // actually sets ALPN
sock.connect("api.github.com", 443);
// Server picks from your list, client can negotiate down to http/1.1
```

### 5. **Replace `readLine()` workarounds on TLS**

If you were using `recvAll()` + manual line parsing on TLS sockets
because `readLine()` returned garbage, you can switch back:

**Before** (0.7.0, workaround):
```cpp
// recvAll + manual line parsing on TLS (because readLine was broken)
auto raw = sock.recvAll(4096);
auto end = raw.find('\n');
std::string line(raw.begin(), raw.begin() + end);
```

**After** (0.7.2, works):
```cpp
// readLine now works correctly on TLS — uses SSL_read internally
auto line = sock.readLine();
```

### 6. **Remove dead config sections from your generated configs**

If you were using `omninet-init` to generate configs, the file no
longer contains dead sections (`security.*`, `dashboard.*`,
`intrusion.*`) that the server silently ignored. Existing config
files still work — the server just ignores those keys. No action
needed unless you want to clean up your generated files.

## Security Improvements (0.7.2)

These changes make HTTPS clients secure by default. If you were
relying on insecure behavior (e.g., accepting any cert for
dev/testing), you'll need to opt out:

```cpp
// To accept any certificate (dev/testing only):
auto ctx = OmniNet::TLSContext::createClient();
ctx->context(); // (you'd need a setter or use raw OpenSSL)

// Or for TLSSocket directly:
TLSSocket sock;
sock.setVerifyMode(TLSVerify::NONE);   // explicit opt-out
```

## Performance Notes

- `TLSContext::createClient()` loads the system CA bundle once
  (~50-200ms on first call, then cached by OpenSSL). Subsequent
  sockets sharing the context reuse the loaded CAs.
- Sharing one context across many sockets saves memory (one
  SSL_CTX per socket → one SSL_CTX for N sockets).
