# OmniNet Bug Reports

This file documents bugs found in OmniNet (third_party) for reporting to the developers.

## Bug #1: HEAD requests not matching GET routes

**Date:** 2026-05-12
**Severity:** Medium
**Component:** Router / HttpServer

### Description
HEAD requests are not matching GET routes in the router. When a GET handler is registered for a path (e.g., `router.get("/blog", ...)`), a HEAD request to the same path returns 404 Not Found instead of being handled by the GET handler.

### Expected Behavior
Per HTTP specification, HEAD method should be handled by the same handler as GET (returning headers only, no body). The router should automatically handle HEAD requests using the matching GET route.

### Current Behavior
- GET `/blog` → Returns 200 OK with HTML content ✓
- HEAD `/blog` → Returns 404 Not Found ✗

### Root Cause
The router's `match()` method only matches exact HTTP methods. When a route is registered with `router.get()`, it only handles GET requests. HEAD requests fall through to the catch-all which returns 404.

### Impact
- Breaks HTTP specification compliance
- HEAD requests to valid endpoints return errors
- Security implications (logging 404s for valid paths)

### Suggested Fix
In `Router::match()`, add logic to treat HEAD requests as GET requests if no explicit HEAD route exists. Alternatively, automatically register HEAD handlers when GET handlers are added.

**STATUS: FIXED** - Modified `Router::match()` to check if a HEAD request has an explicit HEAD route for the path. If not, it falls back to using the matching GET route handler.

**Alternative workaround** (in project code):
Manually register HEAD routes alongside GET routes:
```cpp
router.get("/blog", handler);
router.head("/blog", handler);
```
This is not ideal as it doubles route registration.

## Bug #3: Duplicate route registration not detected

**Date:** 2026-05-12
**Severity:** Low
**Component:** Router

### Description
When the same route is registered multiple times (e.g., duplicate `router.get("/films", ...)` calls), no error or warning is issued. The router silently accepts the duplicate.

### Current Behavior
Line 316 and 324 in main.cpp both register `router.get("/films", ...)` - no warning.

### Impact
- No warning about duplicate routes
- First route is used, subsequent duplicates ignored silently
- Can lead to hard-to-debug routing issues

### Suggested Fix
Add validation to detect and warn about duplicate route registrations.

**STATUS: FIXED** - Added duplicate route detection in `Router::addRoute()` that emits a warning and ignores the duplicate.

## Workaround Strategy

**NOTE: Bug #1 is now FIXED in the library. The workaround is no longer needed.**

For the HEAD request bug (#1), the library now automatically handles HEAD requests using GET routes if no explicit HEAD route exists.

Previous workaround (now obsolete):
```cpp
router.get("/path", handler);    // Handles GET
router.head("/path", handler);    // Handles HEAD (workaround)
```
