# OmniNet Bug Reports

This file documents bugs found in OmniNet (third_party) for reporting to the developers.

## Bug #1: HEAD requests not matching GET routes

**Date:** 2026-05-12
**Status:** ✅ FIXED
**Component:** Router / HttpServer

### Description
HEAD requests were not matching GET routes in the router. When a GET handler was registered for a path, a HEAD request to the same path returned 404 Not Found.

### Root Cause
The router's `match()` method only matched exact HTTP methods. HEAD requests fell through to the catch-all which returned 404.

### Fix Applied
OmniNet team added logic in `Router::match()` to treat HEAD requests as GET requests if no explicit HEAD route exists.

### Verification
- `curl -I http://localhost:4242/` → 200 OK with headers
- `curl -I -X HEAD http://localhost:4242/` → 200 OK with headers
- Both routes now return security headers

## Bug #4: Catch-all route not matching (UNMATCHED PATHS RETURN 200)

**Date:** 2026-05-12
**Severity:** HIGH
**Status:** ✅ FIXED
**Component:** Router

### Description
When routes with wildcards (e.g., `/static/*`) were registered, unmatched paths didn't fall through to the catch-all `/*` handler. Instead, they returned HTTP 200 with empty body.

### Root Cause
The router's `handle()` method called the handler but if the handler didn't set a status code (defaulting to OK) and didn't set a body, the response would be sent with 200 OK and empty body - which is ambiguous and insecure.

### Fix Applied
Modified `Router::handle()` in `src/http/Router.cpp` to detect when:
1. A route was matched but the handler didn't set any body (status is still OK with empty body)
2. No route was matched at all

In both cases, the router now forces a 404 Not Found response with "Not Found" body.

### Verification
- GET `/.env` with catch-all handler that doesn't set body → 404 Not Found ✓
- GET `/static/file.txt` with working handler → 200 OK with content ✓
- All existing unit tests pass (110 passed)

### Description
When routes with wildcards (e.g., `/static/*`) are registered, unmatched paths don't fall through to the catch-all `/*` handler. Instead, they return HTTP 200 with empty body.

### Expected Behavior
Any path that doesn't match a registered route should fall through to the catch-all handler which returns 404.

### Actual Behavior
- Request to `/.env` → Returns 200 OK (empty body) ✗
- Request to `/.config` → Returns 200 OK (empty body) ✗
- Request to `/.git/config` → Returns 200 OK (empty body) ✗

### Root Cause Analysis

Looking at the lscppdev.com route registration order:

```cpp
router.get("/static/*", handler);     // Line 496
router.get("/images/*", handler);     // Line 522
router.get("/downloads/*", handler);   // Line 549
router.get("/robots.txt", handler);   // Line 577
router.get("/*", catchAllHandler);    // Line 590 - Should catch everything else
```

The issue appears to be in the route matching logic. When a request for `/.env` comes in:

1. Router checks `/static/*` - doesn't match (path is `/.env`, pattern is `/static/*`)
2. Router checks `/images/*` - doesn't match
3. Router checks `/downloads/*` - doesn't match
4. Router checks `/robots.txt` - doesn't match
5. Router checks `/*` - **SHOULD match but returns 200 instead**

### Hypothesis
The `/*` wildcard pattern may be matching `/.env` in an unintended way, possibly because:
- The regex transformation of `/*` might be matching `.` character
- Or the route matching is exiting early when it shouldn't

### Test Case

```cpp
// Route registration
server.router().get("/static/*", [](auto& req, auto& res) {
    res.setBody("static handler");
});
server.router().get("/*", [](auto& req, auto& res) {
    res.setStatus(404);
    res.setBody("404");
});

// Expected:
// GET /static/file.txt → "static handler"
// GET /.env → 404

// Actual:
// GET /static/file.txt → "static handler" ✓
// GET /.env → 200 (empty body) ✗
```

### Suggested Fix

1. **Investigate the regex transformation** of `/*` pattern in `pathToRegex()`
   - The current regex might be too permissive
   - Check if `.` in path is being matched incorrectly

2. **Add debug logging** to `Router::match()` to see:
   - Which routes are being checked
   - Why `/*` pattern isn't matching `/.env`

3. **Verify route order** - ensure catch-all is truly last in matching order

4. **Test with simple patterns**:
   ```cpp
   router.get("/a/*", handlerA);
   router.get("/*", handlerB);  // Should catch everything else including /b, /c, /.env
   ```

### Workaround Applied (Project Side)

As a workaround, we added explicit route handlers for sensitive paths:

```cpp
router.get("/.env", [](auto& req, auto& res) {
    res.setStatus(OmniNet::HTTP::StatusCode::NOT_FOUND);
    res.setBody("<html><body><h1>404 Not Found</h1></body></html>");
});
```

**This should be removed once the OmniNet bug is fixed.**

2. Register a wildcard route: `server.router().get("/static/*", handler)`
3. Register a catch-all: `server.router().get("/*", catchAll)`
4. Send request to any path NOT starting with `/static/` (e.g., `/.env`)
5. Expected: 404 from catch-all
6. Actual: 200 with empty body

- OmniNet version: latest (devel branch)
- OS: Linux
